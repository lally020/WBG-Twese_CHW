How the improvement loop works
01 · LABELED CASES
Identify development failures
The runner compares outputs with fixed synthetic labels. Real-world labels would require clinical adjudication.
02 · CANDIDATE UPDATE
Train bounded candidates
Retrain the urgency classifier on development failures and search a fixed set of regularization values and thresholds. Release cases never enter training.
03 · AUTOMATIC CHECKS
Test the selected candidate
Compare the selected candidate against the incumbent on separate frozen cases and workflow regressions.
04 · DEMO ACTIVATION
Activate or retain
Passing candidates replace the demo urgency model automatically. Failed candidates leave it unchanged. The previous model is saved for rollback.
